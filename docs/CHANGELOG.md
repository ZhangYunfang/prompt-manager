# 变更记录

本项目的界面改版记录。打包产物与发版资产见 GitHub Releases。

## 1.6.10

**「复制结果」点了有回执**
- 以前点「复制结果」是**静默**的：复制成功也看不出来，只能自己去别处粘贴试试
- 现在点下去按钮立刻变成「**已复制**」，图标换成**对勾**，整颗按钮填上主题色（默认青色），**1.6 秒后自动变回**「复制结果」
- 没有结果时按钮本来就是灰的、点不动，不会闪这一下
- 点「清除」重新开始时，按钮会先复原成「复制结果」，不会把「已复制」带到下一次结果上

## 1.6.9

**上下两块真正「分开」了**

- 1.6.8 只是把两半塞进分隔条，中间那条缝是看不见的：编辑区和 AI 结果原本共用同一张卡片
- 现在**编辑区、AI 结果各自是一张卡片**，跟左边「我的提示词」、右边「历史记录」同款外轮廓（同底色、同 1px 描边、同 14px 圆角、同 16px 内边距），中间留 6px 缝
- 于是上下之间看到的是「卡片下沿 + 6px 缝 + 卡片上沿」，和左右两列之间看到的一模一样；拖拽手柄就落在这条缝里
- **左右两侧完全没动**，只是中间这一列从「一张卡」变成「两张卡上下叠」

## 1.6.8

**编辑区 / AI 结果上下可拖拽**
- 「编辑区」和「AI 结果」之间加了一条横向拖拽手柄：按住上下拖，自己决定两块各占多高；拖到边也不会把任何一块压成 0
- 默认高度各占一半，想写长提示词就把上半拉大，想看长结果就把下半拉大
- 手柄比原来的左右分栏更细：原来 10px，现在 **6px**（左右分栏同步改成 6px，三处手感一致），鼠标移上去才淡淡显出强调色
- 手柄粗细改 `ui/theme.py` 的 `SPLITTER_HANDLE` 一处，左右与上下分栏一起变

## 1.6.7

**打包版本号修正**
- 1.6.6 的三平台安装包其实都还标着 1.6.5：版本号原本写在两处（关于页 + `build.spec` 的 Info.plist），上一版只改了关于页，打包信息漏改
- 现在版本号只有**一个来源** `config.py` 的 `APP_VERSION`，关于页与 macOS `Info.plist` 都读它，不会再出现「装的是新版、显示的是旧版」
- 「AI 结果」旁的 6 方块加载动画与 1.6.6 相同，无需重新学习

## 1.6.6

**AI 调用进度提示**
- 「AI 结果」标题右边新增 **6 个方块的加载动画**：整理格式 / 优化提示词 一点下去方块从左到右依次点亮，走满 6 格清空重来，AI 结果回来后自动收起
- 方块颜色取当前主题强调色（青色主题即青块，换主题跟着变），未点亮的是同色淡透明，不额外加第二种颜色

## 1.6.5

**Markdown 输出与参考来源**
- 请求末尾统一追加输出要求：用 Markdown 组织内容，并整体用**四个反引号**（````）包裹，避免长文本被截断；展示前自动剥掉外层围栏再渲染
- AI 结果框改为**按 Markdown 渲染**（标题、粗体、列表、表格、代码块），正文里的链接可直接点击用系统浏览器打开
- Markdown 的软换行会把多行并成一段，这里给普通行补硬换行，**排版保持原样**
- 结果文本末尾自动附「**参考来源**」：标题 + 链接（Markdown 链接，可点），复制结果时一并带走
- 来源同时取自**引用角标**与**搜索结果本身**：模型搜了但没在正文打角标时，也能看到搜到的标题和链接

## 1.6.4

**联网搜索与阅读链接**
- 「深度思考」右边新增「联网搜索」勾选：勾上后请求声明 DeepSeek 官方服务端工具 `deepseek_web_search`，由服务端完成搜索，客户端只展示结果（搜索与抓取本身不计费，只算模型 token）
- 只勾「联网搜索」= 普通联网搜索；同时勾「深度思考」= 深度思考搜索（推理中最多约 20 次搜索/打开网页/页内查找，更慢更贵）
- 编辑区内容里出现链接时，自动声明 `deepseek_read_url` 让服务端读取该网页，不需要额外勾选
- 回答带引用时，「AI 结果」右上角出现「参考来源 N」按钮：点开是独立窗口，列出标题与来源站点，双击一行或用「打开原文」调系统浏览器打开原文，另有「复制链接」

## 1.6.3

**AI 结果框显示不完整（修复）**
- 根因：结果框靠 50 ms 定时轮询把流式文本刷上去，流结束时只恢复按钮、**没有再刷最后一帧**，最后一段（常是结尾那句）就停在上一帧
- 现在收尾无条件补刷一次并滚到底，尾巴不再丢
- 解析改按行读（原来一个字节一个字节拼字符串，是 O(n²)；实测 313 KB / 1160 个事件的回复 104 ms → 7 ms，快 14×）
- 强制以 UTF-8 解码流：服务端发不带 `charset` 的 `text/event-stream` 时，requests 会按 ISO-8859-1 解 → 中文乱码、个别片段 JSON 解不出被静默丢弃（换其它 OpenAI 兼容端点时的兜底）
- 状态栏原来报的是左侧**输入**区字数，改成 `完成 · 结果 N 字`

## 1.6.2

**Windows 启动报错修复**
- 换成文件夹版：解压后进 `PromptManager` 文件夹双击 `PromptManager.exe`
- 原因：单文件版每次启动都要把 `PySide6\Qt6Core.dll`（10 MB）等依赖从 exe 里解压到临时目录，杀软拦截或受限的临时目录会让这一步失败，报 `Failed to extract PySide6\Qt6Core.dll decompression resulted in return code -1`。文件夹版没有任何运行时解压步骤，这类报错结构上不会再出现
- 同时关闭 UPX 压缩（同属这类启动解压异常的常见诱因）
- Linux 同步改为文件夹版（`tar.gz` 解压得到 `PromptManager/`）
